# Roadmap

* Предоставлен доступ в GURU. Попробовать опублиоквать precizer в Gentoo.

* Сохранение промежуточных контрольных сумм в цикле независимо от ручного прерывания.

* Восстановить корректную поддержку нескольких корневых путей для обхода файловой системы. Сейчас программа надёжно работает только с одним корневым путём. Ранее в коде существовала поддержка multi-root режима, но она была отключена из-за цепочки взаимосвязанных проблем: файлы из разных корней могли смешиваться, а дальнейшая обработка путей становилась неоднозначной. Теперь найден подход, который позволит однозначно связать каждый файл с его корневым путём и вернуть анализ нескольких директорий без путаницы между ними.

* Постепенно перевести внутренние массивы строк с обычных массивов `char *` на массивы дескрипторов `memory`. Такой подход уже используется для `db_file_paths` и `roots`: он делает владение памятью явным, упрощает освобождение ресурсов и позволяет единообразно использовать проверки библиотеки `mem`. Переход следует выполнять поэтапно, сохраняя текущее поведение программы и добавляя тесты для каждого изменённого участка.

* Прогрессбар (slang?) опциональная сборка с поддержкой прогрессбара

* Вывод сообщений о начале хеширования файла. Сейчас выводится уже результат только после выполненного хеширования. Это связано с предыдущей задачей в roadmap, потому что планируется использоваться библиотека slang для переписывания строки в терминале. Почему именно slang? Эта билбилотека берёт на себя рутину по кроссплатформенной работе с терминалом избавляя от проблем совместимости программы с разными видами терминалов.

* Стабилизация кода и тестов. Выпуск первой стабильной версии 1.0.0

* Улучшение покрытия кода тестами

* Быстрое прерывание длительного сравнения баз данных по Ctrl+C. Сейчас во время выполнения `--compare` программа проверяет запрос на завершение между найденными различиями. Однако если сравниваются большие базы данных и различий мало или нет совсем, SQLite может долго выполнять внутренний поиск без возврата промежуточных результатов. В этот момент Ctrl+C уже будет принят программой, но завершение сравнения может произойти с заметной задержкой.

  Возможный вариант решения: подключить стандартный механизм SQLite `sqlite3_progress_handler()`. Он позволяет периодически вызывать небольшую проверочную функцию прямо во время выполнения SQL-запроса. Эта функция сможет увидеть запрос на завершение и попросить SQLite остановить текущий поиск. Такой подход должен сделать Ctrl+C отзывчивым даже при сравнении очень больших одинаковых баз данных.
